## 2. DSOMM Caddy exec EPERM

Runtime evidence: TrueNAS App STOPPED, Docker container restarting,
exit=255, `/usr/bin/caddy: operation not permitted`, 892 restarts.

Compose had `cap_drop: [ALL]` and `no-new-privileges=true`. Upstream
Caddy's executable may have file effective capabilities; an empty
bounding set causes `execve(2)` to fail `EPERM` **before** Caddy starts.
The reviewed repo fix preserves a minimal bounding capability with
`cap_add: [NET_BIND_SERVICE]`. It is **not** a privilege escalation to
`privileged`. Validate image/runtime configuration before applying:

```bash
sudo docker inspect dsomm --format '{{json .HostConfig.CapDrop}} {{json .HostConfig.CapAdd}} {{.HostConfig.Privileged}}'
sudo docker image inspect wurstbrot/dsomm:4.4.1 --format '{{json .Config.Entrypoint}} {{json .Config.User}}'
sudo docker compose -f apps/dsomm/compose.yml config --quiet
sudo bash scripts/truenas/deploy-dsomm.sh --check
```

After the catalog generators are synchronized and Compose includes the
capability fix, use the supported **DSOMM-only** TrueNAS redeploy
transaction and validate `RUNNING`, healthy HTTP on LAN :31088,
Caddy startup, persisted read-only YAML mounts and stable restart count.
If `EPERM` persists, inspect image filecap, AppArmor/seccomp, mount
`noexec`, container `no-new-privileges` and TrueNAS middleware jobs.
Do not disable all security controls without evidence.

Reference: https://github.com/caddyserver/caddy-docker/issues/396

## 3. Gatus configuration EACCES

Runtime evidence: App STOPPED, Docker restarting exit 2:
`open config/config.yml: permission denied`. Compose mounts
`./config:/config:ro` and uses
`apps/gatus/config/config.yml`, generated by
`scripts/generate-service-consumers.py`.

Read-only checks:

```bash
sudo docker inspect gatus --format 'user={{.Config.User}} {{range .Mounts}}{{.Source}} -> {{.Destination}} readonly={{not .RW}}{{println}}{{end}}'
namei -l /mnt/cpool/compose/nabla-compose/apps/gatus/config/config.yml
stat -c '%U:%G %a %n' apps/gatus apps/gatus/config apps/gatus/config/config.yml
getfacl -p apps/gatus/config apps/gatus/config/config.yml 2>/dev/null | sed -n '1,65p'
```

Fix only the **specific parent-directory traversal ACL and file read
permission** for the **actual Gatus container UID/GID**. On TrueNAS,
ZFS ACLs and execute/traverse rights on each parent matter as much as
the file's read bit. The configuration can include internal URLs and
headers: **do not apply `chmod -R 777` or broaden read permissions to
all users**. Regenerate the config only with the canonical generator
after confirming the removed OpenWebUI Pipelines service; then check
readability from the Gatus UID before restarting the App.
